## 1. User Story — As a / I want / So that
- **As a** Platform Engineer / AI Agent Developer using Sandcastle,
- **I want** a robust, production-grade Sandbox & VM lifecycle management system (featuring hot-restart, automated health checks, self-healing ephemeral environments, snapshoting, and unified OmniRoute-compatible proxy tooling),
- **So that** long-running multi-step agent executions in Sandcastle achieve the reliability, instant warm recovery, and tool parity found in OpenHands Cloud, Devin Web, and OmniRoute while maintaining strict resource isolation and security guardrails.

### Problem Context
Sandcastle already provides solid foundations (Docker.DotNet, Kubernetes engines, WarmPoolService, EgressProxyService, noVNC desktop integration). However, compared to OpenHands Cloud and Devin enterprise architectures, gaps remain in:
1. **VM / Sandbox Lifecycle & Hot Restart**: Lack of an explicit, fine-grained state machine for hot-restarting sandbox containers/VMs without losing workspace volume state or active TTY/bash streams.
2. **Snapshotting & State Restoration**: Absence of lightweight workspace filesystem diff snapshoting for quick checkpoint rollbacks and fork-from-checkpoint.
3. **OmniRoute Tooling Parity & Proxy Consolidation**: Unified handling of proxy tools (search, extract, crawl, map, research) with fallback circuit breakers and BYOR (Bring Your Own Router) LiteLLM integration.
4. **Resilient Health Probing & Auto-Healing**: Enhanced auto-recovery of dead sandbox agent sidecars (`SandboxAgent`) with zero dropped user events.

## 2. Scope
### In Scope
- **Advanced Sandbox State Machine & Hot Restart (`SandboxLifecycleManager`)**: API and orchestrator logic for pause, unpause, hot restart (`POST /api/v1/sandboxes/{id}/restart`), and graceful reclamation.
- **Workspace Volume Snapshoting & Checkpoint Forking**: Lightweight tar-diff snapshoting of sandbox workspaces stored in S3/Local Blob store to enable instant revert and fork.
- **Enhanced Sandbox Agent Health Probing & Auto-Healing**: Active heartbeat between Sandcastle API and `SandboxAgent` sidecar with automatic reconnect and state reconciliation.
- **Unified OmniRoute Proxy Tooling Expansion**: Alignment with OmniRoute tool catalog (op: search, extract, crawl, map, research) with rate limiting, caching, and fallback policies.
- **Diagnostic Session Insights & Telemetry**: Extended metrics for sandbox resource consumption (CPU, RAM, I/O) exposed via `/api/v1/session-insights`.

### Out of Scope
- Rewriting the underlying virtualization kernel (Docker and Kubernetes remain the target container engines).
- Replacing the core Blazor WASM UI layout (enhancements build on top of existing Devin-like components).

## 4. Requirements
- **RF-001 (Sandbox Hot Restart)**: `POST /api/v1/sandboxes/{id}/restart` must restart the container/pod while preserving mounted workspace volumes (`/workspace`) and re-attaching active network and TTY streams within <3 seconds.
- **RF-002 (Workspace Snapshotting)**: The system must support creating a compressed workspace snapshot (`POST /api/v1/sandboxes/{id}/snapshot`) and restoring/forking a conversation from any checkpoint.
- **RF-003 (Sandbox Agent Auto-Healing)**: If the `SandboxAgent` sidecar becomes unresponsive for >5 seconds, the engine must automatically trigger an idempotent re-injection and health probe without dropping user chat events.
- **RF-004 (OmniRoute Proxy Tools v2)**: Consolidate tool execution through `tavily_proxy` with operations `search`, `extract`, `crawl`, `map`, and `research`, including fallback circuit breakers and rate limit backoff.

## 5. API Contract
- `POST /api/v1/sandboxes/{id}/restart` — Restarts sandbox container keeping volume. Auth: Bearer / Cookie. Response: `200 OK` (`{ "status": "restarted", "sandbox_id": "...", "duration_ms": 1240 }`).
- `POST /api/v1/sandboxes/{id}/snapshot` — Creates workspace snapshot. Response: `201 Created` (`{ "snapshot_id": "...", "size_bytes": 45120 }`).
- `POST /api/v1/sandboxes/{id}/restore` — Restores workspace from snapshot. Request: `{ "snapshot_id": "..." }`. Response: `200 OK`.

## 6. Acceptance Criteria
- **Given** a running sandbox conversation with active workspace edits, **When** `POST /api/v1/sandboxes/{id}/restart` is called, **Then** the container restarts successfully, workspace files remain intact, and agent execution resumes seamlessly.
- **Given** a snapshot is created, **When** `POST /api/v1/sandboxes/{id}/restore` is invoked with the snapshot ID, **Then** the workspace filesystem reverts to the exact snapshot state.
